## La forma de una orden

```text
python -m pallaquino_cli <comando> [acción] [argumentos] [opciones]
```

Con el paquete instalado, `pallaquino` equivale a `python -m pallaquino_cli`. Ejemplos reales:

```bash
python -m pallaquino_cli validate --integrity-only --json
python -m pallaquino_cli agents match "agregar autenticación basada en roles" --json
python -m pallaquino_cli memory search arquitectura --json
```

- **Comando**: `validate`, `agents`, `memory`… Hay {meta.counts.commands}.
- **Acción**: algunos comandos agrupan varias (`agents list|match`, `memory status|search|inspect|verify|delete|purge`).
- **Opciones**: empiezan por `--` y van **después** del comando.

## La ayuda integrada

```bash
python -m pallaquino_cli --help
python -m pallaquino_cli memory --help
```

La primera lista los comandos; la segunda, las acciones y opciones de uno concreto. La [referencia de la CLI](../../referencia/cli/) muestra
lo mismo, generado del código.

## Opciones presentes en todos los comandos

| Opción | Para qué |
|---|---|
| `--json` | Salida JSON legible por máquinas (para scripts y para agentes). |
| `--root RUTA` | Raíz del framework. Por defecto: `$PALLAQUINO_ROOT`, luego el checkout del paquete, luego `./.pallaquino` o una carpeta superior. |

## Los comandos por tarea

| Tarea | Comandos |
|---|---|
| Diagnóstico y estado | `doctor`, `validate`, `status`, `stack`, `pipeline`, `graph`, `contracts`, `identity` |
| Análisis | `analyze`, `risk`, `agents`, `skills`, `security` |
| Planificar y ejecutar | `plan`, `run`, `approve`, `pause`, `cancel`, `resume`, `executions` |
| Continuidad | `checkpoint`, `handoff`, `resume` |
| Memoria y proveedores | `memory`, `providers` |
| Herramientas y extensiones | `tools`, `permissions`, `plugins`, `plugin`, `mcp` |
| Instalación en proyectos | `init` |

</Aside>
