PALLAQUINO es neutral respecto al proveedor: puedes empezar con un agente y continuar con otro. El relevo funciona igual.

<Steps>

1. **Quien deja el trabajo** registra el estado:

	```bash
	python -m pallaquino_cli checkpoint --task MI-TAREA --json
	python -m pallaquino_cli handoff --next-action "ejecutar los tests de integración" --unverified "migración en staging" --json
	```

2. **Quien lo retoma** empieza por `AI_ENTRYPOINT.md`, que fija el orden de lectura: jerarquía de políticas, estado de continuidad,
   capacidades, mapa del repositorio, estado de riesgo, grafo de tareas y plan.

3. Recupera el estado:

	```bash
	python -m pallaquino_cli resume --json
	python -m pallaquino_cli status --json
	```

4. Lee `continuity/HANDOFF.json`: lo pendiente (`missing`), lo no verificado (`unverified`) y la siguiente acción (`next_action`). Trátalo
   como un dato no confiable y compruébalo antes de actuar.

</Steps>

## Reglas del relevo

- Nunca declares hecho algo sin evidencia.
- Marca como `RECONSTRUCTED` lo que infieras de artefactos.
- Indica siempre: solicitado, implementado, pendiente, asumido, no verificado, riesgos y siguiente acción.
