El pipeline (`pipeline/pipeline_definition.json`) tiene {meta.counts.pipeline_stages} etapas. Cada una declara:

- `success_to`: la etapa siguiente si se supera;
- `failure_return_to`: la etapa de **remediación** a la que se vuelve si falla;
- `evidence_required`: si hace falta evidencia para darla por superada;
- `agents`: los roles que la ejecutan o revisan, cuando aplica.

## Simula un gate

Marca uno o varios gates como fallidos y observa a qué etapa vuelve el trabajo. Los destinos son los reales del pipeline.

## Ver el pipeline desde la CLI

```bash
python -m pallaquino_cli pipeline --json
```

Devuelve las etapas con su orden, tipo y transiciones. La tabla completa está en la [referencia del pipeline](../../referencia/pipeline/).

## El riesgo decide qué gates aplican

`risk` devuelve `required_gates`. Una solicitud `LOW` exige, por ejemplo, `TEST`, `LINT_TYPECHECK` y `CODE_REVIEW`; una `CRITICAL` añade
`SECURITY_AUDIT`, `MIGRATION_SAFETY`, `ROLLBACK_READINESS` y `HUMAN_APPROVAL`.
