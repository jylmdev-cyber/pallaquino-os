Todo lo de esta lección se comprobó el 2026-10-14 en un proyecto nuevo con `git init`, en Windows con Python 3.11.

## Paso a paso

<Steps>

1. ### Instala el framework en tu proyecto

	Desde `pallaquino-os/universal_ai_fullstack_orchestrator`, primero en seco y después de verdad:

	```bash
	python -m pallaquino_cli init --target ../mi-proyecto --dry-run --json
	python -m pallaquino_cli init --target ../mi-proyecto --json
	```

	**Resultado esperado:** `"copied": 383` y `"dry_run": false`. Se crea `mi-proyecto/.pallaquino/`. Los archivos existentes nunca se
	sobrescriben (`"skipped"` cuenta los que ya existían). Cambia `../mi-proyecto` por la ruta real de tu repositorio.

2. ### Elige cómo ejecutar la CLI

	`init` copia también el paquete `pallaquino_cli` dentro de `.pallaquino`. Tienes dos opciones:

	<Tabs>
		<TabItem label="Sin instalar nada (recomendado para empezar)">
			Trabaja **desde** `.pallaquino`: Python encuentra allí el paquete y la raíz es esa misma carpeta.

			```bash
			cd ../mi-proyecto/.pallaquino
			python -m pallaquino_cli status --json
			```

			Si lo ejecutas desde `mi-proyecto/` verás `No module named pallaquino_cli`.
		</TabItem>
		<TabItem label="Con el paquete instalado">
			Si instalaste el paquete (`python -m pip install -e ./universal_ai_fullstack_orchestrator`), el comando `pallaquino`
			usa por defecto **el checkout del paquete**, no tu proyecto. Indica la raíz con `--root`, que va **después** del subcomando:

			```bash
			pallaquino status --root .pallaquino --json
			```

			También puedes exportar la variable `PALLAQUINO_ROOT` con la ruta de `.pallaquino`.
		</TabItem>
	</Tabs>

3. ### Fija tu identidad de commits

	<Aside type="caution" title="Hallazgo de la auditoría">
		`init` copia `governance/git_identity.json` tal cual, así que tu proyecto empieza esperando la identidad del **mantenedor del
		framework**. Mientras no la cambies, `doctor` y `validate --json` fallarán en `validate_git_authorship`.
	</Aside>

	Desde `.pallaquino`:

	```bash
	python -m pallaquino_cli identity --json
	python -m pallaquino_cli identity --name "Tu Nombre" --email tu@correo.example --json
	python -m pallaquino_cli identity --apply-local --json
	```

	- El primero muestra la identidad esperada y la configurada en tu repositorio.
	- El segundo guarda **tu** identidad en `governance/git_identity.json` (requiere `--name` y `--email` juntos).
	- El tercero la escribe en la configuración **local** de Git de tu proyecto (nunca en la global).

	**Resultado esperado:** `"matches": true`. Desde ese momento `python -m pallaquino_cli doctor` termina con código 0.

	<Aside type="note" title="Nombres con tildes en Windows">
		Desde 0.5.1, los nombres con acentos o eñes (por ejemplo `Ana Pérez`) funcionan en Windows. En 0.5.0, `identity --apply-local`
		devolvía `"matches": false` con esos nombres; si todavía usas 0.5.0, actualiza a 0.5.1. Más información en
		[Solución de problemas](../../referencia/solucion-de-problemas/).
	</Aside>

4. ### Comprueba el resultado

	```bash
	python -m pallaquino_cli doctor
	```

	**Resultado esperado:** `"ok": true` y código de salida 0.

</Steps>

<Aside>
	En el **clon del framework** (`pallaquino-os`) no cambies la identidad: allí la comprobación verifica los commits del mantenedor y es
	normal que falle en tu equipo. Comprueba la integridad con `validate --integrity-only --json`.
</Aside>
